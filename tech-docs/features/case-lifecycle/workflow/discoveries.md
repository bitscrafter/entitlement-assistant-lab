| 1 | Spec defect (security) | S27k showed the contact's `roles_in_subject` while the subject is not readable: roles in an account are facts about it, so they would reveal something the CSR may not read (AU-6). | Amended under security over speed: `roles_in_subject` is `null` unless the subject is readable too (D15, S27k). For the owner's review. |
| 2 | Plan gap | The account step denies every action but reads on a suspended subject, so S33j (a subject on hold) and S27i (a contact on hold) would be refused. | The lifecycle keys `case.set-subject`, `case.set-contact`, `case.authenticate-contact`, `case.close` join the actions allowed on a suspended account: they act on the case, not on the account (as AU-1's terminating and read exceptions). |
| 3 | Plan gap | The access step looks up the permission named like the action, so the lifecycle keys would need permissions of their own. | A governing-permission map in the access step: the four lifecycle keys are held through `case.open` (D11, SU-14). |
| 4 | RED (passes) | Six tests pass before the build: S33d case B, S34c cases A–D, S34f case B. Each expects `404`, which any missing route answers today (S34c case D, the upgrade, is already enforced by explain-access: a closed case has no assignee). | Kept, as in explain-access (its discoveries 11, 12). Proven in P4: removing the assignee check fails S34c A–C, letting a missing account through fails S33d B and S34f B; S34c D is explain-access's upgrade rule, proven there. |
| 5 | Spec defect (Given) | S33h's Given ended an assignment of support-case-handling, but iac_alex holds that role as a birthright (customer-support representative), so nothing was removed. | The Given is a transfer to finance as an analyst, which ends the birthright role; the scenario's When and Then are unchanged. |
| 6 | Platform (live) | Closing a case in production: the agent closed its one connection (`case-connections-closed`, 1) and a raw client received the close frame `4404 case_unavailable` at once; Node's WebSocket client reported nothing within 5 s, as it waits for the TCP connection to end. Browsers report the close on the close frame. | K1 passes in production and in the Workers runtime test (S34b). The count of closed connections stays in the log. |
| 7 | Design | The case panel offers **Set as contact** on an account a lookup by email showed as the person's own (an `ambiguous` candidate with `own_account`, or the one account `found` by email); the server still refuses any other account (D3). | For the owner's review in the browser. |
| 8 | Adversarial review, round 1 (2026-10-26) | REJECT: 2 major, 7 minor. R1 an authentication could be recorded for a contact changed concurrently (decided on Jane, written for Bob); R2 a subject, contact, or authentication could be written to a case closed concurrently; both because the assignee check read the case without a lock and the audit chain's lock made the interleaving deterministic. R3 a drafted summary could mention accounts readers of the subject may not read; R4 a turn or connection could outlive the close; R5 a CSR who loses read on the subject cannot close the case; R6 three reason codes missing from the register; R7 the spec disagreed with itself on `roles_in_subject` without a subject; R8 a misplaced doc comment; R9 drift in api.md §9 and SU-14, and a whitespace-only summary accepted. Sound: assignee rule, AU-6 ordering, case view and past cases, authorization changes, model influence, the RPC method, the subject rule, D13, tests. | R1, R2: every action locks the case row in the case assignee check (reading the case does not); reproduced deterministically without the lock (16 race runs fail) and fixed with it. R3: drafts about the subject only, a warning in the close form. R4: the WebSocket message guard closes `4404` and the tools refuse once the case is no longer assigned (the plan's K1 fallback, as a second line). R5: kept AU-4; recorded in production-readiness, for the owner. R6–R9 fixed. |
| 9 | Adversarial review, round 2 (2026-10-26) | ACCEPT: every round-1 fix verified; no lock-order inversion (lifecycle actions lock the case row, then the audit chain head; no path takes them the other way). Minor: R2-1 a failing case check before a tool call reached the model as a raw error; R2-2 the case check costs one more transaction per message and per tool call, and runs in a separate transaction from the use case; R2-3 the case check's wiring was tested only with doubles; R2-4 a non-assignee briefly waits on a busy case's row lock. | R2-1 fixed (the check inside the tool's error handling). R2-3 fixed: a Workers-runtime test closes a case in the tables and sends a message on the open connection (`4404`, no model call); removing the wiring fails it. R2-2 kept: Hyperdrive pools the connections, and a read slipping between the check and the use case is still authorized and audited. R2-4 kept: it needs a guessed case id. |
